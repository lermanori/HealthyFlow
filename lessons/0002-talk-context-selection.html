One skill: trace the evidence for a Talk answer

Before Talk can answer,
it needs a read plan.

The user does not ask for “seven Calendar days plus every Goal and Habit.” They ask one question. The architecture first resolves what that question refers to, then reads the sources required to answer it.

The key distinction: deciding what to read is separate from deciding what to say. The first decision must happen before the iPhone sends Calendar data to the backend.

The rule to keep

Three checks before a claim

  1. Right scope: did the plan resolve the user's date and subject from the conversation?
  2. Right sources: did it read every source required for that claim?
  3. Honest status: was each read successful, empty, missing, or failed?

A provider such as Jev might help select finite source options. It still has to pass these checks, especially Hebrew follow-ups and open-ended dates.
