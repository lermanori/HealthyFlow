HealthyFlow · Native boundary lesson 001

One Siri capture, five boundaries

The goal is not “let Siri create Tasks.” The goal is “let Siri preserve a thought, then let the person review it in Talk.” That distinction keeps capture fast and HealthyFlow safe.

Invariant: dictated text is a pending capture, not an Item. It must not call AI, consume credits, or write product records until the user reviews and sends it from Talk.

The complete path

System

Siri

Resolves a required text parameter, asking “What should I add?” when needed.
Swift

App Intent

Validates and timestamps the text. Returns a short spoken acknowledgement.
Storage

App Group queue

Persists the capture locally under group.app.healthyflow.mobile.
Bridge

Capacitor plugin

Lets React list, read, and acknowledge pending native captures.
React

Talk

Loads the text into the composer as an editable draft. Nothing is auto-sent.

Why local-first is the right v1

ChoiceWhat it buys usCost
App Group queueWorks offline, needs no native auth token, and reuses the app/widget entitlement already configured.Capture initially exists only on that device.
Upload immediatelyCross-device availability.Swift needs a securely mirrored HealthyFlow token in Keychain, token refresh, retry/idempotency, and a new capture API.
Put text in a deep-link URLVery little code.Leaks private text into URLs/logs, has length/encoding failure modes, and is not a durable queue.

The Swift shape

This sketch shows ownership, not paste-ready final code. One deep native module should own the capture schema, store, intent, shortcut provider, and Capacitor bridge.

import AppIntents

struct AddToHealthyFlowIntent: AppIntent {
    static var title: LocalizedStringResource = "Add to HealthyFlow"
    static var authenticationPolicy: IntentAuthenticationPolicy = .alwaysAllowed

    @Parameter(title: "Capture")
    var text: String

    static var parameterSummary: some ParameterSummary {
        Summary("Add \(\.$text) to HealthyFlow")
    }

    func perform() async throws -> some IntentResult & ProvidesDialog {
        try HealthyFlowCaptureStore.append(text)
        return .result(dialog: "Captured. Open HealthyFlow to review it in Talk.")
    }
}

struct HealthyFlowShortcuts: AppShortcutsProvider {
    static var appShortcuts: [AppShortcut] {
        AppShortcut(
            intent: AddToHealthyFlowIntent(),
            phrases: [
                "Add to \(.applicationName)",
                "Capture with \(.applicationName)"
            ],
            shortTitle: "Add to HealthyFlow",
            systemImageName: "waveform.badge.plus"
        )
    }
}

The HealthyFlow handoff

1 · Peek
The authenticated React shell asks the native plugin for the oldest pending capture on launch and foreground.
2 · Route
Navigate to /talk?capture=<uuid>. Only the opaque ID belongs in the URL.
3 · Hydrate
AssistantPage reads the ID, fetches the text through the plugin, and places it in draft.
4 · Acknowledge
Remove the capture from the native queue only after the composer has accepted it.

States worth designing explicitly

StateExpected behavior
Offline or backend downCapture still succeeds because it is local.
User logged outKeep the queue untouched; load it after login.
Talk already has a draftDo not overwrite. Show “Siri capture ready” with an explicit Insert action.
Several captures pendingReview oldest first or expose a small inbox; never silently discard.
App crashes during handoffThe capture remains because acknowledgement happens last.
Version gate blocks the appThe App Group queue remains intact until a supported version opens.
