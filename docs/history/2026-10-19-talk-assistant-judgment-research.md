# Talk assistant judgment: research note

19 October 2026. This is a research snapshot and recommendation, not a description of shipped behavior.

## The general problem

Given a user question, conversation state, and partial/noisy app evidence, how should Talk choose the smallest useful read, identify what matters to this person, make only supported claims, and give one useful next move? Retrieval completeness, factual grounding, and good judgment are separate qualities. In the captured week interaction, the Calendar read was complete while the answer still repeated a holiday, treated an all-day holiday as a definite conflict, and gave the dentist appointment too little emphasis.

Today the path is `Talk -> /ai/chat/context-plan -> selected Calendar/Day reads on the client -> /ai/chat -> answer`. The first model call chooses dates and sources. The second receives compact Calendar evidence and a long general system prompt. The current calendar instruction to mention every distinct title protects against omitted appointments but pulls the response toward an event inventory.

## What the research suggests

1. **Curate context for the decision, not for maximum volume.** Anthropic's [context-engineering guidance](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) recommends the smallest high-signal context and warns against long lists of edge-case rules. [Lost in the Middle](https://arxiv.org/abs/2307.03172) found that relevant facts can be used less reliably depending on where they occur in a long input. This supports the compact Calendar index but also suggests the main user-relevant commitments should be made prominent rather than merely included.
2. **Content planning is promising, not a guaranteed quality boost.** [Chawla et al., EACL 2024](https://aclanthology.org/2024.eacl-long.142/) studied explicit content plans for grounded dialogue. Some variants improved automatic metrics while doing worse in human judgment. A new `answer-plan` call should therefore be an experiment against human preference, not a default architectural commitment.
3. **Use code for facts it can prove and the model for qualitative judgment.** [Google Research's hybrid trip-planning work](https://research.google/blog/optimizing-llm-based-trip-planning/) separates qualitative preferences from hard logistical constraints. For Talk, date spans, timed overlaps, empty/unavailable reads, and provenance can be calculated or typed. Whether a reserve-duty week makes a dentist appointment worth checking is a judgment, so it should be expressed as a possibility unless hours or other evidence prove the conflict.
4. **Evaluate the interaction, not just fact recall.** [Anthropic's agent-evaluation guide](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) recommends combining deterministic checks, model rubrics, and human review for conversational agents; it explicitly distinguishes capability tests from regression tests. [OpenAI's agent-evaluation guide](https://developers.openai.com/api/docs/guides/agent-evals) recommends tracing a workflow first, then moving successful examples into repeatable datasets. This matches the trace we captured, but the current tests mostly check context and prompt construction, not whether an answer feels useful.
5. **More agents are not automatically better.** [Google Research's 2026 study](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/) found multi-agent gains for parallel tasks and losses for sequential planning tasks. Talk's read-to-answer path is mostly sequential; an extra agent or verifier should need measured improvement to justify latency, cost, and more failure points.

## Recommended experiment

Keep the existing read planner. Build a private, de-identified replay set starting with the three captured Hebrew turns and adding cases for ambiguous dates, unavailable Calendar, all-day events, exact timed overlaps, source/origin follow-ups, and unrelated app data. Preserve exact evidence and expected **claims**, but never commit personal event details or full conversations.

Compare three answer variants on the same replay set: (A) current prompt/model; (B) a short answer contract that asks for the most consequential commitment first, evidence-backed uncertainty second, and at most one relevant next step; (C) variant B with a stronger model. Only if B/C still fail should we test a separate structured content-planning call. A single call could first produce a typed answer outline internally, but this also needs comparison rather than assumption.

Score each answer on five independent dimensions: (1) factual coverage of the user's actual question, (2) unsupported or overstated claims, (3) priority of consequential commitments over calendar noise, (4) useful uncertainty and a relevant next step, and (5) unnecessary repetition or canned filler. Add deterministic checks for dates, event titles, read statuses, and timed-overlap claims; use blind human pairwise preference for “which reply would help you act?” Calibrate any model judge against those human decisions. Track latency and provider cost alongside quality.

The target week answer should lead with reserve duty across the week and the Monday 09:00–11:30 appointment, note that their compatibility needs checking because reserve-duty hours are unknown, then group lower-priority holiday entries briefly. It should not imply that an all-day public holiday itself proves a conflict or that the app knows which subscribed Calendar supplied a generic event when no source field was read.
